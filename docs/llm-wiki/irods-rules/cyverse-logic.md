`cyverse_logic.re` is the largest rule file (about 2,760 lines). Its header
documents each policy area and gives JSON Schema definitions for every published
AMQP message. [cyverse_core.re](/irods-rules/cyverse-core.md) calls its
`cyverse_logic_*` rules from most PEPs.

## Policy areas

- **AMQP message publishing.** User events are published as JSON to the topic
  exchange named by `cyverse_AMQP_EXCHANGE`. `_cyverse_logic_sendMsg` runs the
  `amqp-topic-send` command script on `cyverse_RE_HOST`, which reads the broker
  URI from `IRODS_AMQP_URI`. Nothing is sent when the author is the local zone's
  `anonymous` user, because iRODS doesn't let `anonymous` run command scripts
  (https://github.com/irods/irods/issues/5016). Failures are logged, not
  raised. See [AMQP Broker](/components/amqp-broker.md).
- **UUIDs.** Every collection and data object gets a type 1 UUID in the
  `ipc_UUID` AVU, generated by the `generate-uuid` command script. Messages
  identify entities by this UUID.
- **Checksums.** Uploads without `regChksum` or `verifyChksum` get a checksum
  computed asynchronously: `_cyverse_logic_schedChksumRepl` schedules
  `cyverse_logic_chksumRepl` on the delay queue, which runs
  `ichksum-exec -M -f -n <repl> <path>` for a replica with no checksum.
- **Protected AVUs.** Attributes starting with `ipc` can only be added,
  modified, or removed by `rodsadmin` users; other attempts fail with -830000.
  `adda` is exempt from this pre-check. AVU copies (`imeta cp`) copy only
  allowed AVUs, never `ipc_UUID`, then deliberately fail with status 0 and
  `CYVERSE SUCCESS: Successfully copied the allowed metadata.` so iRODS doesn't
  also copy the protected ones.
- **rodsadmin group permissions.** New collections and data objects give the
  `rodsadmin` group `own` under `/<zone>/home/` and `/<zone>/trash/home/`, and
  `write` elsewhere. Changing the `rodsadmin` group's permission to any other
  level fails with -830000 unless it is an administrative (`admin:`) ACL change.
  (The header says "own permission on all collections and data objects"; the
  code grants `write` outside home and trash home.)
- **Resource free space.** After a parallel transfer or data copy is received,
  `msi_update_unixfilesystem_resource_free_space` runs on the resource's host.
- **TLS policy.** `cyverse_logic_acPreConnect` returns `CS_NEG_REFUSE`.

## Published topics

Topics are `<type>.<event>`, where the type is `collection` or `data-object`:

| Event | Topics |
| --- | --- |
| Create | `collection.add`, `data-object.add` |
| Move/rename | `collection.mv`, `data-object.mv` |
| Remove | `collection.rm`, `data-object.rm` |
| ACL change | `collection.acl.mod`, `data-object.acl.mod` |
| Data object modified / opened | `data-object.mod`, `data-object.open` |
| System metadata modified | `data-object.sys-metadata.mod` |
| AVU operations | `<type>.metadata.add`, `.adda`, `.rm`, `.set` (via `.metadata.<op>`), `.mod`, `.rmw`, `.cp`; `data-object.metadata.addw` |

The header's schema list has a few typos in topic names (e.g.
`data object.metadata.cp` and `data object.sys-metadata.mod` with a space, and
`collection.metadata.adda` given for the "AVU Set" message). The code builds
topics from `_cyverse_logic_getMsgType`, which returns `collection`,
`data-object`, `resource`, or `user`.

## Rules called from cyverse_core.re

- **Static PEPs:** `acPreProcForModifyAccessControl`,
  `acPostProcForModifyAccessControl`, `acPreProcForModifyAVUMetadata` and
  `acPostProcForModifyAVUMetadata` (three arities each), `acCreateCollByAdmin`,
  `acPostProcForCollCreate`, `acDeleteCollByAdminIfPresent`,
  `acPreprocForRmColl`/`acPostProcForRmColl`, `acPreConnect`,
  `acPostProcForDataCopyReceived`, `acDataDeletePolicy`/`acPostProcForDelete`,
  `acPostProcForOpen`, `acPostProcForObjRename`,
  `acPostProcForParallelTransferReceived` — each prefixed `cyverse_logic_`.
- **Catalog events:** `cyverse_logic_dataObjCreated` (sets admin permission and
  UUID on `START`/`FULL`) and `cyverse_logic_dataObjMetaMod`.
- **API PEPs:** `cyverse_logic_api_*` for bulk put, copy, put, physical path
  registration, replica open/close, touch, and data object
  create/open/write/close. The create/open/write rules record state in
  `temporaryStorage` and the close rule schedules checksums and publishes
  `data-object.add` or `data-object.mod`.

`acPreprocForRmColl` and `acDataDeletePolicy` record the entity's UUID in
`temporaryStorage` before removal, and the matching post-processing rules publish
the `.rm` message with it. Rules such as `acPostProcForOpen` and
`acPostProcForModifyAccessControl` publish only when
`cyverse_isCurrentAction` shows no other `cyverse_logic` action is already
registered for the entity.

`cyverse_logic_api_data_obj_put_post` is reached through `acPostProcForPut`
since the iRODS issue 8106 workaround; see
[cyverse_core.re](/irods-rules/cyverse-core.md#issue-8106-workaround).

## Dependencies

Uses [cyverse.re](/irods-rules/cyverse.md) (helpers, action tracking,
`cyverse_setProtectedAVU`, constants) and
[cyverse_json.re](/irods-rules/cyverse-json.md) (message serialization and
touch and replica-close input parsing). Included by
[cyverse_core.re](/irods-rules/cyverse-core.md).

## Tests

`playbooks/tests/rules/cyverse_logic.py` has 44 test methods, more than half
marked skipped or not implemented, covering the ID, user info, and AVU helpers
and `acPostProcForModifyAVUMetadata`; the static and dynamic PEP test groups
are entirely skipped or unimplemented. The
shared module setup in `playbooks/tests/rules/test_rules.py` installs
`mocks/amqp-topic-send` in place of the real command script.
`mocks/cyverse_logic.re` stubs this file for `cyverse_core.re` tests.
